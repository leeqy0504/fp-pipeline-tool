算子模型开发 Pipeline — 整体架构

方案 1：可组合的独立 CLI 工具链，每个阶段松耦合通过标准化中间格式连接

Pipeline 全景

FPipe 工具链架构
fpipe-collect
→
传感器采集 | 标注辅助 | 格式标准化
输入: 传感器/手动采集  →  输出: raw/ 目录
fpipe-clean
→
深度/掩码校验 | 无效帧过滤 | 标注修正 | 数据增强
输入: raw/  →  输出: clean/ + metadata.json
fpipe-train
→
数据加载 | 配置管理 | 训练/验证 | 指标输出
输入: clean/ + model_config.yaml  →  输出: weights/ + metrics/
fpipe-deploy
→
模型导出 ONNX/TRT | 推理引擎封装 | Benchmark
输入: weights/  →  输出: deploy/
fpipe-serve
→
REST/gRPC API | 请求队列 | 健康检查 | 指标暴露
输入: deploy/  →  续行: 推理服务实例

标准化中间格式

fpipe 数据集目录规范 (FPipe Format)
my_dataset/
├── raw/                          # fpipe-collect 产出
│   ├── scene_000/
│   │   ├── rgb/000.png, 001.png
│   │   ├── depth/000.png, 001.png
│   │   ├── camera_intrinsics.json
│   │   └── annotations.json     # (可选) GT 标注
│   └── scene_001/...
│
├── clean/                        # fpipe-clean 产出
│   ├── scene_000/
│   │   ├── rgb/                  # 过滤后图像
│   │   ├── depth/                # 过滤后深度
│   │   └── annotations.json     # 修正后标注
│   ├── scene_001/...
│   └── metadata.json            # 数据集级元信息
│
├── weights/                      # fpipe-train 产出
│   └── foundationpose/
│       ├── best.ckpt
│       ├── config.yaml
│       └── metrics.json
│
└── deploy/                       # fpipe-deploy 产出
    └── foundationpose/
        ├── model.onnx
        ├── model_config.json
        └── benchmark.json
